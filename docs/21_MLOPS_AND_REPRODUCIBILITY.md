## 1. Reproducibility Requirements

Reproducibility is a fundamental requirement across the entire platform. If a trade opportunity is generated or a backtest is run, a user must be able to exactly replicate that decision later.

### 1.1 Global State Tracking

To guarantee reproducibility, every significant action (Backtest, ML Ranking, or Signal Engine opportunity generation) must record:

| Element | Description |
|---|---|
| `dataset_version` | Timestamp of the latest data point available in the database |
| `feature_pipeline_version` | Git hash or semantic version of the feature engineering code |
| `strategy_version` | Semantic version of the strategy logic |
| `strategy_parameters` | Exact dictionary of parameters |
| `ai_model_version` | Identifier for the LLM or ML model |
| `decision_mode` | Strategy-Only, AI-Only, or Hybrid |
| `execution_mode` | Backtest, Paper, or Live |

## 2. ML Strategy Selection Lifecycle

### 2.1 Model Registry
While MLFlow or Weights & Biases are industry standards, the MVP can use a lightweight PostgreSQL-backed model registry to store:
* Model binary (or S3 link)
* Training date
* Training features used
* Out-of-sample validation metrics (Accuracy, F1, LogLoss)

### 2.2 Training Pipeline
The training pipeline for the strategy ranking model must enforce strict temporal splitting (Purged CV / Walk-forward) to prevent data leakage.
